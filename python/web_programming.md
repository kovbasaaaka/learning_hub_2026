### Интернет и Web-технологии

Интернет это глобальная сеть компьютеров, объединённая физическим и сетевым образом.

`Web` это 1 из сервисов интернета на ряду с email, ftp и так далее.

**Хронология событий**:

- 1969 год, появление ARPANET(сеть, используемая в военных целях)
- 1989 год - 1991 год, Тим Бёрнс-Ли разрабатывает концепцию под названием `WWW` в которую входят `HTML`, `HTTP`, `URL`;
- 1993 год, появление первого графического браузераа `Mosaic`;
- 1995-2000 годы, первая эволюция веба `WEB 1.0`, появляются первые статичные страницы, но предназначенные для режима чтения(только чтения)
- 2000 годы, вторая эволюция веба `WEB 2.0`, появились интерактивные социальные сети, пользовательский контент;
- 2010 годы, полноценный мобильный `WEB`, появились одностраничные приложения.
- 2020 годы, современный `WEB`, входит в микросервисы, серверный и клиентский рендеринг и AI-интеграции.

### Клиент-серверная структура

**Клиент-серверная структура** - это модель взаимодействия в которой одна
программа(клиент) запрашивает ресурсы или услуги у другой программы(сервера) с помощью `API` посредством отправки запросов и получением ответов.

Свойства модели:

- **ассимметрия ролей**, если сервер обычно один либо кластер, то клиентов, обращающихся к серверу множество;
- **разделение ответственности**, сервер хранит данные, а клиент эти данные отображается, взаимодействуя с пользователем.
- 1 компьютер может быть как клиентом, так и сервером.

### `P2P`

Также существует альтернативная структура - `P2P`, где узлы полностью равноправны.


### `DNS`

`DNS` - система доменных имён(Domen name system).

### `HTTP`

`HTTP` - это протокол прикладного уровня для передачи гипертекстов.


Например возьмём адрес: `https://www.example.com:443/products/list/?category=phones&sort=price#reviews`

- `HTTPS` - это защищённый протокол `HTTP` или по другому - **схема** того, как передаются данные;

- `www.example.com` - это **хост**, т.е. местоположение сервера;

- `443` - это **порт**, т.е. точка подключения на сервере;

- `products/list` - это **путь** к запрашиваемому ресурсу;

- `category=phones&sort=price` - `query-parametrs`, т.е. **дополнительные параметры**;

- `#reviews` - это **якорь**, т.е. ссылка на нужную часть страницы, обрабатываемая только 
клиентом.

### Виды `HTTP` запросов

#### `GET`

Необходим для **получения данных**.

#### `POST` 

Необходим для создания **новых данных**, например, отправка формы регистрации.

#### `PUT`

Необходим для **полного обновления** данных, например при обновлении профиля пользователя.

#### `PATCH`

Необходим для **частичного обновления** данных.

#### `DELETE`

Необходим для удаления данных.

### Статус код `HTTP` запросов

Имеют вид трёхзначного числа, в основном используются такие сигнатуры:

- 1XX, отвечает за продолжение работы запроса;
- 2XX, отвечает за успешность выполнения запроса;
- 3XX, отвечает за перенаправление запроса;
- 4XX, отвечает за ошибки со стороны клиента;
- 5XX, отвечает за ошибки со стороны сервера.


Где `XX` - это разные цифры.

2 всё хорошо, 3 не туда, 4 ошиблись вы, 5 ошибся он.

### `HTTPS`

Данный протокол отвечает за защиту передаваемых данных путём:

- **шифрования**, т.е. невозможности свободного прочтения данных перехватчиком;
- **целостности**, т.е. невозможности незаметной подмены данных;
- **аутентификации**, т.е. уверенности клиента в подлинности сервера.

### Что представляет из себя клиент?

Клиент представляет собой **браузер**.

**Браузер** - это **клиентское приложение**, которое отправляет `HTTP` запросы, получает ответы и интерпретирует их для показа пользователю с помощью **языков разметки**.

**Основные компоненты браузера**:

1. `user interface`(UI) - адресная строка, кнопки навигации и закладки;
2. `brauser engine` - связывает `UI` и движок рендеринга;
3. **Движок рендеринга** - разбирает `HTML` и `CSS` и строит визуальное отображение.
4. **Движок Java Script** - разбирает JS код;
5. **Нетворкинг** - отвечает за `HTTP` запросы, `DNS`, `Cashe`;
6. **Хранилище данных** - отвечает за хранение `cookies`, баз данных и других данных.

### `Frontend` и `Backend`

Frontend:

- выполняется в браузере клиента;
- отвечает за отображение интерфейса, взаимодействие с пользователем;
- функционирует с помощью `HTML`, `CSS`, `JS`, `TypeScript`.
- фреймворки `React`;
- что видит пользователь - видит стиль страницы, её дизайн и т.д.
- взаимодействует с пользователем и бэкендом.

Backend:

- выполняется на сервере;
- отвечает за работу с данными;
- функционирует с помощью `Python` и других языков программирования;
- что видит пользователь - результат работы с данными;
- фреймворки `Django`, `Flask`, `FastAPI`;
- взаимодействует с данными и фронтендом.

## Лекция 2. - HTML


**HTML** - это набор команд интерпретируемых браузером при загрузке документа и перед показом пользователю.

**Элементы** - это конструкции языка **HTML**. Контент содержащий данные и позволяющий форматировать их должным образом.

**Дескрипторы** - это элементы, которые определяют внешний вид и поведение веб-страницы.

**Тег** - это начальный или конечный маркер элемента, который определяет границы одного действия.

В **HTML** теги объединяются **двойными скобками `<тег></тег>`**. Первый тег это открывающий, второй - закрывающий. 

**Атрибуты** - это свойства элементов.

**Гиперссылка** - это фрагмент текста, который ссылается на любой другой объект.

`<a></a>` - тег для ссылки.

`<href></href>` - тег для гиперссылки.

**Фрейм** - это область документа со своей областью прокрутки.

**HTML файл** - это документ, созданный на основе гипертекстов с расширением `html`.

### HTML5

Преимущества:

1. **Семантические теги**. Семантика это использование тегов, которое отображает их смысл, а не только визуальное оформление: `<nav>`, `<header>`, `<main>`.

2. **SEO-ориентированная структура**: 

- ранжирование заголовков: `<h1></h1>` - должен фигурировать 1 раз. Так вторая цифра идёт вплоть до 6 и заголовок уменьшается в размере отображения.

- `<head><method lang = ...></head>

- Есть чёткая навигация благодаря семантическим тегам

- Использование атрибута alt.

- Семантические ссылки.


3. **Доступность** - это возможность сайта быть пригодным для всех людей. Почему важно чтобы сайт был доступен:

- Этическая сторона
- Юридическая сторона
- Практическая польза


Форма это основной способ получения данных от пользователя.

Основные форматы данных:

1. Текст;
2. Формат электронной почты;
3. Пароль;
4. Числовой;
5. Номер телефона;
6. Дата;
7. Поле с отметкой;
8. Ползунок значений;
9. Выбор нескольких значений из диапазона;
10. Файл, загрузка файлов;
11. поле поиска.
