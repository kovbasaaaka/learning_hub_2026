### Интернет и Web-технологии

Интернет это глобальная сеть компьютеров, объединённая физическим и сетевым образом.

`Web` это 1 из сервисов интернета на ряду с email, ftp и так далее.

**Хронология событий**:

- 1969 год, появление ARPANET(сеть, используемая в военных целях)
- 1989 год - 1991 год, Тим Бёрнс-Ли разрабатывает концепцию под названием `WWW` в которую входят `HTML`, `HTTP`, `URL`;
- 1993 год, появление первого графического браузераа `Mosaic`;
- 1995-2000 годы, первая эволюция веба `WEB 1.0`, появляются первые статичные страницы, но предназначенные для режима чтения(только чтения)
- 2000 годы, вторая эволюция веба `WEB 2.0`, появились интерактивные социальные сети, пользовательский контент;
- 2010 годы, полноценный мобильный `WEB`, появились одностраничные приложения.
- 2020 годы, современный `WEB`, входит в микросервисы, серверный и клиентский рендеринг и AI-интеграции.

### Клиент-серверная структура

**Клиент-серверная структура** - это модель взаимодействия в которой одна
программа(клиент) запрашивает ресурсы или услуги у другой программы(сервера) с помощью `API` посредством отправки запросов и получением ответов.

Свойства модели:

- **ассимметрия ролей**, если сервер обычно один либо кластер, то клиентов, обращающихся к серверу множество;
- **разделение ответственности**, сервер хранит данные, а клиент эти данные отображается, взаимодействуя с пользователем.
- 1 компьютер может быть как клиентом, так и сервером.

### `P2P`

Также существует альтернативная структура - `P2P`, где узлы полностью равноправны.


### `DNS`

`DNS` - система доменных имён(Domen name system).

### `HTTP`

`HTTP` - это протокол прикладного уровня для передачи гипертекстов.


Например возьмём адрес: `https://www.example.com:443/products/list/?category=phones&sort=price#reviews`

- `HTTPS` - это защищённый протокол `HTTP` или по другому - **схема** того, как передаются данные;

- `www.example.com` - это **хост**, т.е. местоположение сервера;

- `443` - это **порт**, т.е. точка подключения на сервере;

- `products/list` - это **путь** к запрашиваемому ресурсу;

- `category=phones&sort=price` - `query-parametrs`, т.е. **дополнительные параметры**;

- `#reviews` - это **якорь**, т.е. ссылка на нужную часть страницы, обрабатываемая только 
клиентом.

### Виды `HTTP` запросов

#### `GET`

Необходим для **получения данных**.

#### `POST` 

Необходим для создания **новых данных**, например, отправка формы регистрации.

#### `PUT`

Необходим для **полного обновления** данных, например при обновлении профиля пользователя.

#### `PATCH`

Необходим для **частичного обновления** данных.

#### `DELETE`

Необходим для удаления данных.

### Статус код `HTTP` запросов

Имеют вид трёхзначного числа, в основном используются такие сигнатуры:

- 1XX, отвечает за продолжение работы запроса;
- 2XX, отвечает за успешность выполнения запроса;
- 3XX, отвечает за перенаправление запроса;
- 4XX, отвечает за ошибки со стороны клиента;
- 5XX, отвечает за ошибки со стороны сервера.


Где `XX` - это разные цифры.

2 всё хорошо, 3 не туда, 4 ошиблись вы, 5 ошибся он.

### `HTTPS`

Данный протокол отвечает за защиту передаваемых данных путём:

- **шифрования**, т.е. невозможности свободного прочтения данных перехватчиком;
- **целостности**, т.е. невозможности незаметной подмены данных;
- **аутентификации**, т.е. уверенности клиента в подлинности сервера.

### Что представляет из себя клиент?

Клиент представляет собой **браузер**.

**Браузер** - это **клиентское приложение**, которое отправляет `HTTP` запросы, получает ответы и интерпретирует их для показа пользователю с помощью **языков разметки**.

**Основные компоненты браузера**:

1. `user interface`(UI) - адресная строка, кнопки навигации и закладки;
2. `brauser engine` - связывает `UI` и движок рендеринга;
3. **Движок рендеринга** - разбирает `HTML` и `CSS` и строит визуальное отображение.
4. **Движок Java Script** - разбирает JS код;
5. **Нетворкинг** - отвечает за `HTTP` запросы, `DNS`, `Cashe`;
6. **Хранилище данных** - отвечает за хранение `cookies`, баз данных и других данных.

### `Frontend` и `Backend`

Frontend:

- выполняется в браузере клиента;
- отвечает за отображение интерфейса, взаимодействие с пользователем;
- функционирует с помощью `HTML`, `CSS`, `JS`, `TypeScript`.
- фреймворки `React`;
- что видит пользователь - видит стиль страницы, её дизайн и т.д.
- взаимодействует с пользователем и бэкендом.

Backend:

- выполняется на сервере;
- отвечает за работу с данными;
- функционирует с помощью `Python` и других языков программирования;
- что видит пользователь - результат работы с данными;
- фреймворки `Django`, `Flask`, `FastAPI`;
- взаимодействует с данными и фронтендом.

## Лекция: Взаимодействие клиента и сервера: Fetch, GET, POST, CRUD, CORS

### Два способа общения с сервером


```
Классика:   клик → запрос → сервер → НОВАЯ ВСЯ СТРАНИЦА → мигание экрана

Fetch:      клик → JS шлёт запрос → сервер → JSON-данные
                                                 │
                        JS меняет только нужный кусок страницы (DOM)
```

### Немного истории
- Конец 1990-х — 2000-е: технология **AJAX** (запросы из JS через объект `XMLHttpRequest`). Так появились Gmail и Google Maps.
- 2015+: современный встроенный инструмент — **`fetch`**. Короче, удобнее, работает с промисами.

### Аналогия

`fetch` — это курьер. Вы (JavaScript) даёте ему адрес и поручение, он едет на сервер, а вы пока занимаетесь другими делами. Когда курьер вернётся с ответом, вы им воспользуетесь.

**Вывод:** страница = клиент, JS в ней сам умеет быть клиентом и общаться с сервером. Интерфейс (frontend) и данные (backend) общаются через запросы и JSON.


### GET

Свойства:

- Только читает: не должен ничего менять на сервере;
- Данные в адресе: параметры идут в URL после  '?';
- Можно повторять: повторный запрос даст тот же результат;
- Кэшируется: браузер может запомнить ответ;
- Тела у запроса нет: все что нужно серверу - в адресе и заголовках.

### Параметры запроса


```
/api/users?limit=2&q=иван
           └──┬──┘ └──┬──┘
           ключ=значение, пары через &
```

Для безопасной подстановки текста в адрес используем `encodeURIComponent`:

```js
const q = 'иван петров';
const url = `/api/users?limit=2&q=${encodeURIComponent(q)}`;
// /api/users?limit=2&q=%D0%B8%D0%B2%D0%B0%D0%BD%20%D0%BF%D0%B5%D1%82%D1%80%D0%BE%D0%B2
```

Пробелы, кириллица и символы `&`, `?` в адресе «ломают» его, поэтому их кодируют.

### Простейший GET

```js
const response = await fetch('/api/users');   // GET — метод по умолчанию
const users = await response.json();          // превращаем JSON в объект
console.log(users);
```

**Важное правило:** никогда не передавайте пароли и личные данные через GET — адрес остаётся в истории браузера, в логах сервера, в закладках.

## Fetch: промисы, async/await, ошибки (15 мин)

### Проблема: сеть — это долго

Ответ приходит не мгновенно (десятки и сотни миллисекунд). Если бы JS стоял и ждал, страница бы «зависла». Поэтому `fetch` **асинхронный**: он сразу возвращает **промис** («обещание»), а результат придёт позже.

```
Промис — это «расписка» о будущем результате. У него три состояния:

  pending (ожидание) ──► fulfilled (выполнен: есть ответ)
                    └──► rejected  (отклонён: ошибка сети)
```

### Два способа писать

**Современный — `async/await`** (читается сверху вниз, как обычный код):

```js
async function getUsers() {
  const response = await fetch('/api/users');
  const users = await response.json();
  show(users);
}
```

**Через `.then()`** (встречается в старом коде):

```js
fetch('/api/users')
  .then(response => response.json())
  .then(users => show(users))
  .catch(error => show('Ошибка: ' + error.message));
```

`await` можно использовать только внутри функции со словом `async`.

### Два `await` — почему?

1. `await fetch(...)` — ждём, пока придут **заголовки ответа** (статус и т.д.).
2. `await response.json()` — ждём, пока придёт и разберётся **тело** ответа.


### ⚠️ Главная ловушка fetch

**`fetch` не считает ошибкой ответ 404 или 500.** Промис отклоняется только тогда, когда запрос вообще не удалось выполнить (нет сети, сервер недоступен, запрещено CORS). Ответ с кодом 404 — это *успешно полученный* ответ, просто сервер сказал «не нашёл».

Поэтому всегда проверяем `response.ok`:

```js
async function getUser(id) {
  const response = await fetch(`/api/users/${id}`);
  if (!response.ok) {
    show(`Ошибка: ${response.status} ${response.statusText}`);
    return;
  }
  const user = await response.json();
  show(user);
}
```

### Полный надёжный шаблон

```js
async function safeGet(url) {
  try {
    const response = await fetch(url);
    if (!response.ok) {
      throw new Error('HTTP ' + response.status);   // ошибка от сервера
    }
    const data = await response.json();
    show(data);
  } catch (error) {
    show('Не получилось: ' + error.message);        // сюда попадут и ошибки сети
  }
}
```

## POST 

**POST** — «вот данные, создай новый ресурс». Данные отправляются в **теле запроса**.

### Как отправить JSON

```js
async function createUser(name, email) {
  const response = await fetch('/api/users', {
    method: 'POST',                                      // 1. метод
    headers: { 'Content-Type': 'application/json' },     // 2. «внутри JSON»
    body: JSON.stringify({ name, email })                // 3. тело — строка
  });
  if (!response.ok) {
    const err = await response.json();
    show(`Ошибка ${response.status}: ${err.error}`);
    return;
  }
  const created = await response.json();
  show(created);
}
```

Три обязательных части: **метод**, **заголовок `Content-Type`**, **тело** (через `JSON.stringify`, потому что тело — это строка, а не объект).

### Распространённые заблуждения
- **«POST безопасен»** — нет. Тело запроса не видно в адресной строке, но по сети оно идёт открытым текстом. Защищает только **HTTPS** (лекция 1).
- **«Проверка в форме достаточна»** (`required`, `pattern`) — нет. Браузерную проверку легко обойти, поэтому сервер всегда проверяет данные сам.

### Отправка обычной формы (кратко)
Если нужна отправка файлов или обычной HTML-формы, используют `FormData`:

```js
const form = document.querySelector('form');
const data = new FormData(form);
await fetch('/upload', { method: 'POST', body: data });  // Content-Type браузер поставит сам
```

## CRUD 

**CRUD** — четыре базовые операции с данными. Почти любое приложение (соцсеть, магазин, список задач) состоит из них.

| Буква | Операция | SQL | HTTP-метод | Пример адреса | Успешный ответ |
|-------|----------|-----|------------|---------------|----------------|
| **C**reate | Создать | `INSERT` | `POST` | `POST /users` | 201 Created |
| **R**ead | Прочитать | `SELECT` | `GET` | `GET /users`, `GET /users/5` | 200 OK |
| **U**pdate | Обновить | `UPDATE` | `PUT` / `PATCH` | `PUT /users/5` | 200 OK |
| **D**elete | Удалить | `DELETE` | `DELETE` | `DELETE /users/5` | 204 No Content |

### Правила REST-адресов (повторяем лекцию 1)
- Адрес называет **вещь** (существительное, обычно во множественном числе): `/users`, `/products`.
- **Действие** задаёт HTTP-метод, а не адрес.

```
✗ плохо:   POST /createUser     GET /deleteUser?id=5
✓ хорошо:  POST /users          DELETE /users/5
```

### PUT и PATCH: в чём разница

| | PUT | PATCH |
|---|-----|-------|
| Что отправляем | Ресурс **целиком** (все поля) | Только **изменяемые** поля |
| Пример тела | `{"name":"Анна","email":"new@x.ru"}` | `{"email":"new@x.ru"}` |
| Аналогия | Заменить всю страницу в тетради | Исправить одно слово |

### DELETE и ответ 204
Сервер ответил «готово» и **ничего не прислал в теле**. Значит, `response.json()` вызывать нельзя — будет ошибка:

```js
async function deleteUser(id) {
  const response = await fetch(`/api/users/${id}`, { method: 'DELETE' });
  if (!response.ok) throw new Error('Ошибка ' + response.status);
  // 204 No Content: тела нет
}
```

### Цикл работы типичного интерфейса

```
 Пользователь жмёт «Добавить»
        │
        ▼
 JS: fetch POST /users  ───►  Сервер: проверяет, пишет в БД ───► 201 + новая запись
        │                                                                │
        ▼                                                                │
 JS: fetch GET /users   ◄──────── свежий список ◄────────────────────────┘
        │
        ▼
 JS: перерисовывает таблицу (DOM)
```

После любого изменения лучше заново запросить данные: интерфейс показывает то, что реально лежит на сервере.
