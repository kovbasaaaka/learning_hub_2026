## Объект Series

### Основные понятия

С помощью `pandas` нам обычно приходится работать с двумерными данными в виде таблиц со столбцами и строками, называемых **датафреймами**.

В то же время **каждый столбец** представляет собой одномерную структуру, именуемую **Series**. 

<img width="397" height="290" alt="image" src="https://github.com/user-attachments/assets/e82c11a7-1eb6-4e2a-a41e-871ebca37649" />

Таким образом, можно представлять датафрейм как коллекцию объектов **Series**.

Это бывает очень полезно, поскольку вскоре станет понятно, что большинство методов, применимых к объектам **Series**, могут быть использованы и с **датафреймами** с той лишь разницей, что вместо единственного значения они будут возвращать значения **для всех столбцов в датафрейме**.

К примеру, если применить к объекту **Series** метод `mean`, он вернёт **среднее значение по столбцу**, но если вызвать его применительно к **датафрейму**, `pandas` под капотом опросит **все входящие в датафрейм столбцы на предмет среднего значения** и вернёт полученные результаты совокупно в виде нового объекта **Series**, к которому в последствии также можно применить разные методы.

<img width="372" height="192" alt="image" src="https://github.com/user-attachments/assets/444a6c4c-94df-4647-9504-2bdd60c62710" />

Наиболее важным и мощным инструментом, который есть у нас, как у разработчиков на `pandas`, является **индекс** (`index`), который можно использовать для отбора значений как из объектов **Series**, так и из **датафреймов**. 

**Series** - представляет собой одномерный массив с метками, который может хранить данные любого типа. Он состоит из двух основных компонентов: собственно данных и индекса.

**Данные** в **Series** представляют собой значения или элементы любого типа данных и могут быть предоставлены в виде:
- словаря **Python**;
- списка **Python**;
- кортежа **Python**;
- массива **NumPy**;
- скалярных значений;
- других структур данных.

При всём при этом нужно понимать, что объект **Series** имеет фиксированный размер и форму после создания.

Он может содержать лишь определённое количество элементов, которое является **неизменяемым**.

При наличии пропущенных данных объект **Series** представляет их как значения **NaN**(Not-a-Number), предоставляя методы для эффективной обработки и манипулирования пропущенными значениями.

Надо понимать, что **Series**, хотя и похожи на списки **Python**, которые могут содержать элементы разных типов данных, объекты **Series** больше подходят для работы с **однородными данными**. Т.е. с данными одного типа.

- Например:
  ```python
  import pandas as pd

  s = pd.Series([100, 200, 300, 400, 500]) # цены на товары в рублях
  s2 = pd.Series(['100р', 'Двести рублей', 'Триста рублей', 400, 500.5]) # допустим это те же данные, но уже   неоднородные
  
  print(f"Однородные данные:\n\n{s}\n")
  print(f"Неоднородные данные:\n\n{s2}\n")

  ```
  выводит:
  ```python
   Однородные данные:
  
  0    100
  1    200
  2    300
  3    400
  4    500
  dtype: int64
  
  Неоднородные данные:
  
  0             100р
  1    Двести рублей
  2    Триста рублей
  3              400
  4            500.5
  dtype: object
  ```
  Здесь наглядно показана разница между неоднородными и однородными данными.

Почему важна однородность и **Series** предпочтительнее использовать именно с однородными данными:
- Во первых - Скорость. Однородные данные в **Series** хранятся в виде массива С-типов, как в `NumPy` и операции над ними выполняются на уровне процессора, т.е. довольно быстро.
- Во вторых - Память. `int64` - это 8 байт на число. `object` - это указатель на объект **Python** + сам объект, что в разы больше.
- В третьих - Функциональность. Многие методы для **Series** работают только с числами или только с определённым типом данных, тогда как на объекты типа `object` они либо не работают, либо дают неожиданный результат и ломают код.
- В четвёртых - Предсказуемость. Когда понятно, что все элементы **Series** однородны, то можно спокойно применять к ним необходимые методы не боясь ошибок в коде и зная, какой будет результат.

### Создание объекта Series

Для создания объекта применяется такой код: `pd.Series(data=None, index=None, dtype=None, name=None, copy=None)

Здесь ключевыми являются два параметра.

Параметр `data` - данные, на основании которых строится объект, и параметр `index`, который указывает, как индексировать данные.

Остальные параметры:

- dtype - отвечает за указание явного типа данных (например, `int64`, `float64`, `str`). Если оставить значение `None`, `pandas` попытается сам определить тип данных на основе переданных данных `data`;
- name - отвечает за имя/название для всей создаваемой серии. Полезно, когда эта серия превращается в отдельный столбец внутри таблицы `DataFrame`;
- copy - отвечает за копирование входных данных. Если установлено `True` - создаётся физическая копия переданного массива в памяти, иначе не создаётся.

### Создание Series на основе списка, кортежа, словаря, скалярного значения и массива Numpy

- Выглядит так:
  ```python
  import pandas as pd
  import numpy as np
  
  list_to_series = pd.Series([1, 2, 3, 4, 5])

  print(f"На основе кортежа:\n{tuple_to_series}\n")
  print(f"На основе скалярного значения:\n{scalar_value_to_series}")
  ```
  выводит:
  ```python
  На основе списка:
  0    1
  1    2

  3    4
  4    5
  dtype: int64
  
  На основе массива Numpy:
  ```

#### Из какой структуры данных лучше создавать объект Series?

Исходя из логики и вида **Series** использовать структуру данных `dict` из **Python** лучший выбор, если нужны готовые смысловые метки, ведь в данном случае ключи словаря автоматически представляются как индексы, а значения - как данные.

Для работы с большими числовыми объёмами и максимальной производительности можно использовать массив из **NumPy**, т.к. библиотека `pandas` построена поверх `numpy`, данные передаются напрямую без лишнего копирования и переупаковки типов.

В чём проблема использовать просто список из **Python**(`list()`)?

А проблема заключается в том, что в **Python** индексы у списков строго неизменяемы, т.е. начинаются с 0, могут быть только типа данных `int` и это никак не изменить. 
А у объектов типа **Series** индексы можно и иногда даже нужно изменять, они могут принимать как числовые, так и строковые значения и необязательно начинаться с 0. Но это не основная проблема, так как `index` можно легко кастомизировать. 
Основная проблема заключается в динамической типизации. 

В **Python** каждый элемент списка является полноценным отдельным объектом и чтобы это работало **Python** хранит в списке не сами значения, а ссылки на них в памяти.

В `pandas` же, данные в памяти лежат плотным непрерывным блоком одного типа, например ровно 64 бита на каждое число.

Но всё же создание на основе списков удобно для быстрого тестирования или небольших последовательностей данных.

**Скалярная величина** используется, когда необходимо заполнить всю серию определённым повторяющимся значением. Но при таком создании будет требоваться задание обязательного параметра `index`, т.к. скаляр размножается под каждую метку.

- Например:
  ```python
  import pandas as pd

  s = pd.Series(5, index=['a', 'b', 'c'])
  print(s)
  ```
  выводит:
  ```python
  a 5
  b 5
  c 5
  ```

Исходя из всего этого напрашивается вывод, что структуру данных необходимо выбирать исключительно под конкретные задачи, так как каждый вариант обладает своими преимуществами.

### Применение индексов

В примерах выше мы использовали только один параметр - `data`, т.е. сами данные. 

Но параметр `index` позволяет более точно настроить сопоставление данных с индексами и настроить индексацию.

Этот параметр представляет метки или имена, присвоенные каждому элементу в серии. Он помогает идентифицировать и получать доступ к конкретным элементам **Series**. По умолчанию индекс начинается с 0 и увеличивается на 1 для каждого элемента, но его можно настроить на любую последовательность меток.

- Например, мы хотим создать серию с одним и тем же значением, которое повторяется несколько раз, допустим значение 67, которое повторяется 6 раз:
  ```python
  import pandas as pd

  value = 67

  series = pd.Series(value, index=[0, 1, 2, 3, 4])
  print(series)
  ```
  выводит:
  ```python
  0 67
  1 67
  2 67
  3 67
  4 67
  dtype: int64
  ```

Аналогичным образом мы можем настроить произвольные индексы на произвольные элементы. Причём в качестве индексов необязательно должны выступать числа. 

- Например, пусть у нас есть список возрастов разных людей, и мы хотим каждому возрасту присвоить метку человека с таким возрастом:
  ```python
  import pandas as pd

  ages = [67, 52, 42]
  names = ["Bob", "Bilbo", "Pudge"]

  s = pd.Series(ages, index=names)
  print(s)
  ```
  выводит:
  ```python
  Bob 67
  Bilbo 52
  Pudge 42
  dtype: int64
  ```

#### Обращение к элементам серии по индексу

Индексы играют важную роль, прежде всего потому, что позволяют обращаться к элементам в серии подобно тому, как мы можем обращаться к элементам списка в **Python**.

- Например:
  ```python
  import pandas as pd

  ages = [67, 52, 42]
  names = ["Bob", "Bilbo", "Pudge"]
  
  s_with_custom_index = pd.Series(ages, index=names)
  s_with_standart_index = pd.Series([67, 52, 42, 69])
  
  print('До изменений\n')
  print(f'{s_with_custom_index}\n')
  
  s_with_custom_index['Bob'] = 192
  s_with_custom_index['Bilbo'] = 5
  s_with_custom_index['Pudge'] = 1999
  
  print('После изменений\n')
  print(s_with_custom_index)
  
  # получаем элементы по индексам
  
  print('Получаем элементы\n')
  print(f'По строковому индексу: {s_with_custom_index['Pudge']}\n')
  print(f'По стандартному индексу: {s_with_standart_index[0]}\n')
  
  # изменяем по стандартному индексу
  
  print('До изменений\n')
  print(f'{s_with_standart_index}\n')
  
  s_with_standart_index[3] = 79
  
  print('После изменений\n')
  print(s_with_standart_index)
  ```
  выводит:
  ```python
  До изменений

  Bob      67
  Bilbo    52
  Pudge    42
  dtype: int64
  
  После изменений
  
  Bob       192
  Bilbo       5
  Pudge    1999
  dtype: int64
  
  Получаем элементы
  
  По строковому индексу: 1999
  
  По стандартному индексу: 67
  
  До изменений
  
  0    67
  1    52
  2    42
  3    69
  dtype: int64
  
  После изменений
  
  0    67
  1    52
  2    42
  3    79
  dtype: int64
  ```

В примере выше было показано, как можно обращаться по индексам к элементам объекта **Series**. Как можно заметить, в серии `s_with_standart_index` мы не задавали индексы, поэтому они создавались автоматически - начиная с 0. 

Явная установка индексов как в серии `s_with_custom_index` позволяет получить больший контроль и придать элементам серии более читабельные метки.

Причём используя набор индексов мы можем получить часть серии, которая состоит из соответствующих элементов и использовать срезы.

- В качестве примера возьмём серии из кода выше:
  ```python
  ages = [67, 52, 42]
  names = ["Bob", "Bilbo", "Pudge"]
  
  s_with_custom_index = pd.Series(ages, index=names)
  s_with_standart_index = pd.Series([67, 52, 42, 69])
  
  subseries1 = s_with_custom_index[["Pudge", "Bob"]]
  subseries2 = s_with_standart_index[[0, 1, 2]]
  
  print(f"Без помощи срезов:\n\n{subseries1}\n\n{subseries2}\n")
  print(f"С помощью срезов:\n\n{subseries1["Pudge":"Bob"]}\n\n{subseries2[:3]}")
  ```
  выводит:
  ```python
  Без помощи срезов:

  Pudge    42
  Bob      67
  dtype: int64
  
  0    67
  1    52
  2    42
  dtype: int64
  
  С помощью срезов:
  
  Pudge    42
  Bob      67
  dtype: int64
  
  0    67
  1    52
  2    42
  dtype: int64
  ```

### Свойства Series

Объект **Series** обладает рядом свойств, которые могут потребоваться при работе с сериями `pandas`, а именно:
- Имя серии;
- Размер серии;
- Уникальность элементов;
- Количество значений в серии;
- Тип данных.

Рассмотрим все эти свойства.

#### Имя серии

Присвоение имени объекту **Series** повышает ясность и контекст данных, улучшает читаемость кода, облегчает интерпретацию данных и упрощает совместную работу.

В `pandas` существует несколько способов присвоить имя объекту `Series`. 

Вот несколько распространённых подходов:
